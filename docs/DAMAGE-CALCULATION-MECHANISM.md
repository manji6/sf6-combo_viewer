# ダメージ計算（補正値計算）の仕組み — クラシック確定版

作成日：2026-09-13。対象：`src/lib/damage/`（`calculate.ts` / `ruleset.ts` / `types.ts`）。

[archive/DAMAGE-CALCULATION-DESIGN.md](archive/DAMAGE-CALCULATION-DESIGN.md) は実装前の設計・調査メモ（未確定事項の洗い出し）。本ドキュメントはその後、**オーナーが実際に対戦画面で確認した実測値との答え合わせを繰り返して確定した、クラシック操作限定の計算ロジック**をまとめたもの。設計メモにあった不確定要素の多くはここで決着している。

## 1. 位置づけ・スコープ

- **クラシック操作は実測で確定済み**。対戦画面（トレーニング/リプレイのダメージ表示）で実際に確認できた値をオーナーが報告し、それにエンジンの計算値を一致させる形で確定した。community 記事の一般式をそのまま採用したものではない（参考にはしたが、最終的には実測で裏取りしている）。
- **モダン操作の簡易入力補正（0.8倍）は2026-09-13に追加実装**。ただし対象技ごとに「モダン専用の簡易入力（SPボタン）が実在するか」を技辞典の `Move.inputModern` で確認できて初めて計算できるため、未確認（`inputModern: null`）の技を含むコンボはモダン計算では `status:'incomplete'` になる（推測で埋めない）。とくにスーパーアーツ（SA1〜3、CA）は現時点で全て `inputModern` 未確認のため、SAで締めるコンボのモダン計算は軒並み incomplete になる。詳細は §4.9。
- 現状は **監査専用**。`src/pages/damage-audit/index.astro`（開発時のみ・本番404、`?modern=1` でモダン表示に切替）と `npm run damage:audit -- --modern` から使え、公開ページのダメージ表示には未接続（`Route.damage` / `Combo.damageOverride` の手入力値がそのまま表示され続けている）。
- 検証範囲：クラシックはマノン・ブランカの実戦コンボ21件中17件が完全一致、残り4件は後述の「既知の制限」で差分の理由が説明できている（＝未解決の謎はない）。モダンは実測値がまだ無く、テストは公式フレームデータ自体が示す倍率（後述）の再現のみで検証している。

## 2. 全体の計算フロー

`calculateComboDamage(combo, ruleset, controlType)`（`src/lib/damage/calculate.ts`）が、コンボの `routeChain` を先頭から辿り、`Step` を1つずつ処理する。`controlType`（`'classic' | 'modern'`、既定は `'classic'`）を `'modern'` にすると §4.9 のSPボタン簡易入力補正が有効になる。

```text
Combo.routeChain（Route[]） を順に走査
  → 各 Route.steps を順に処理
    → moveKey が無く command が DR/DRC/CDR → 「以降 DR係数を掛ける」フラグを立てるだけ（段は進めない）
    → action（whiff/feint 等）付き → 非ヒット。whiff/feint なら段をリセット（補正切り）
    → moveKey 付き → 1ヒットとして下記の順で計算し、内訳を記録
  → Route の到達先 situation が「補正切り」タグを持つ → 段・即時補正・DR フラグをリセット
→ 全ヒットのダメージを合計
```

1ヒットぶんの計算順序（`guaranteedPercent` の doc コメントに準拠）：

```text
① 段（stage）に対応する残存率を引く（stageScalingPercent テーブル）
② パニッシュカウンターなら基礎ダメージに ×1.2
③ 即時補正の累計ポイントを②の残存率から減算（自分の分も含む。始動ヒットは対象外）
④ ドライブラッシュ以降なら残存率に ×0.85
④' controlType:'modern' かつ SPボタン簡易入力の対象技なら残存率に ×0.8（§4.9）
⑤ SA技かつ最低保証があれば、④までの値を下回っていれば保証値まで引き上げる（下限）
⑥ 残存率を floor → 基礎ダメージ × 残存率 ÷ 100 を floor
⑦ SA3固有の rondpoint キャンセルボーナスがあれば固定 +50
```

## 3. 用語対応表（公式サイトの説明 ↔ 実装）

2026-09-13、オーナーが公式サイトの補正値説明ページの文言を確認・共有してくれたことで、以下の対応が判明した。

| 公式の説明 | 実装 | 効果 |
|---|---|---|
| 始動補正＝「コンボの初段にヒットさせた際に加算される補正」 | `parseStarterScalingPercent`（`Move.comboScaling` の `"始動補正N%"`） | この技が**コンボの最初のヒット**なら、以降のヒットの段を1つ前進させる（`stage` の初期値が1→2）。技自身のダメージには影響しない |
| コンボ補正＝「コンボの2段目以降にヒットさせた際に加算される補正」 | `parseComboCorrectionPercent`（`"コンボ補正N%"`） | 始動補正と同じ「段を1つ前進」だが、**始動技である必要がない**（2段目以降でも発動）。技自身には掛からない |
| 即時補正＝「コンボの2段目以降にヒットさせた際、その技自体に加算される補正」 | `parseImmediateScalingPercent`（`"即時補正N%"`） | 技自身の残存率からNポイントを引き、かつ**以降の全ヒットにも持続**する（累積・重ね掛けあり）。始動ヒットには自己適用しない |
| 乗算補正＝「コンボに組み込んだ際に、それ以降のコンボ補正値に乗算される補正値」 | `driveRushMultiplier`（0.85） | 生ドライブラッシュ（DR/DRC/CDR）以降の全ヒットの残存率に一度だけ掛かる（重ね掛けしない） |
| （公式の直接記載なし。実測で判明） | パニッシュカウンター判定（`isPunishCounterCommand`） | 該当ヒットの**基礎ダメージ**に ×1.2（残存率とは別枠） |
| （SA3固有の注記＋実測で判明） | `SA3_CANCEL_BONUS_*` | manon-sa3 をロン・ポワン（強/弱いずれも）または立ち強Pからキャンセルで出すと、保証適用後の値に**固定+50**ダメージ |

## 4. 各要素の詳細

### 4.1 段階補正（基本の残存率テーブル）

```text
stageScalingPercent = [100, 100, 80, 70, 60, 50, 40, 30, 20, 10]
```

- `stage`（1始まり）ごとに上記テーブルを引く。テーブルの範囲外（11段目以降）は下限の10%を使う。
- 段は「実際にダメージが発生したヒット」ごとに1つ進む。`Move.damage === 0` の技（フィアーダウン等の移動・設置技）は段を消費しない（DR/DRC/CDR と同じ扱い）。

### 4.2 始動補正・コンボ補正（段の前進）

- 始動補正：コンボの最初のヒットである技が持っていれば、`stage` の初期値を1ではなく2にする（＝以降のヒットが1段先に進んだ扱いになる）。技自身の残存率は通常通り100%（1段目）のまま。
- コンボ補正：始動補正と同じ「1段前進」だが、コンボの何段目でも発動しうる。技自身には掛からず、押し出す形で以降だけ前進させる（`stage += 2` として実装。次のヒットが通常の+1より1段多く進む）。
- 実装上は同じ「段を余分に1つ進める」効果だが、発動条件（初段限定か否か）が異なるため別々の正規表現・別々のフィールド意味で扱っている。

### 4.3 即時補正（自分＋以降への累積減算）

- `即時補正N%` を持つ技がヒットすると、その時点の残存率から N ポイントを引く。この技自身にも適用される。
- 引いた N は `immediateOffset` に加算され、以降の全ヒットの残存率からも継続して引かれ続ける。
- 同じ技を複数回使うと重ね掛けされる（例：画面端補正切りコンボで弱グランフェッテを2回使うと2回目以降さらに10ポイント追加）。
- **例外**：コンボの最初のヒット（単発の投げなど）には自己適用しない。始動補正と同様、始動そのものにペナルティを課さない。
- **例外**：`manon-sa3` は一般化した即時補正パーサの対象から除外している（後述4.6）。
- **注意**：この補正は `Move.damage === 0` の技（フィアーダウン等）にも設定されうる。0ダメージ技は段を消費しないが、`即時補正` タグがあれば `immediateOffset` には正しく加算される（ブランカの `blanka-sa2` の即時補正10%が、段を消費せずにライトニング・ビースト中の後続技すべてに効いていることを確認）。

### 4.4 ドライブラッシュ（乗算補正）

- `DR` / `DRC` / `CDR` のいずれかの `command` を持つ step（`moveKey` を持たない）を通過すると、以降の全ヒットの残存率に **一度だけ** ×0.85 が掛かる（フラグ方式。DRを複数回挟んでも重ね掛けしない）。
- 適用順は「即時補正の減算のあと」。

### 4.5 SA最低保証

- `Move.comboScaling` の `"最低保[障証]N%"` を持つ超必殺技（`category === 'super'`）に適用。
- **DR係数を掛けたあとの値に対する下限**として扱う（保証が成立した後にさらにDR等を掛け直すことはしない）。
- `manon-mid-5mp-lethal-sa3` の実測（DR併用のSA3がちょうど保証50%になる）で、この順序（DR→保証)を確定した。設計段階では「保証→DR」の可能性もあったが、実測で否定されている。

### 4.6 SA3（マノン）固有のロン・ポワンキャンセルボーナス

- 技辞典の `manon-sa3.comboScaling` には「最低保証50%。立ち強P・ロン・ポワンからのキャンセル時のみ即時補正15%」という注記があるが、実際の挙動は率ではなく **固定+50ダメージ**（最低保証適用後の値に加算）。
- 弱ロン・ポワンからキャンセルした実測 `2050 = 4000×50%保証 + 50` で確認。強Pからのケースは未確認だが、技辞典の注記が両方を並べて書いているため同じ扱いにしてある。
- 一般化した「即時補正」パーサでは表現できない技固有の例外のため、`calculate.ts` に直接ハードコードしている（`SA3_MOVE_KEY` / `SA3_CANCEL_BONUS_SOURCE_RE` / `SA3_CANCEL_BONUS_DAMAGE`）。

### 4.7 パニッシュカウンター（PC）

- `Step.command` に notation の PC メタトークン（例: `"PC 5HK"`）が含まれる場合、その1ヒットの**基礎ダメージ**に ×1.2。
- 強K・強P・ドライブインパクトの3例、いずれも合計値が完全一致することを確認済み。残存率側には影響しない（基礎ダメージへの倍率として扱う）。

### 4.8 補正切り（リセット）

段・即時補正累計・DRフラグを初期状態に戻すトリガーは2種類：

1. `Step.action === 'whiff' | 'feint'`：空振り・フェイントでコンボを意図的に切る（強ランヴェルセを当てずにスカす、等）。
2. 到達先 `Situation.tags` に `"補正切り"` が含まれる：空振りを挟まないケース（ターゲットコンボの浮かせ直し等）。Route境界をまたいだ後、次のヒットの前でリセットする。

### 4.9 モダン操作の簡易入力補正（2026-09-13 追加）

- **確認できた事実**（複数の解説記事＋公式フレームデータの数値裏取り）: モダン操作の「SPボタン」で必殺技・コマンド投げを出すと、コマンド入力（クラシック的な操作）で出した場合の**80%（×0.8）**のダメージになる。モダン操作中でも**コマンド入力（`Move.inputModernPrecise`）で出せば据え置き**（軽減を回避できる）。
- 公式フレームデータ自体が根拠になっている：マノンの弱/中/強/OD マネージュ・ドレ、弱/OD ランヴェルセは「■クラシック操作」「■モダン操作時」のダメージが並記されており、Lv1基準でいずれも厳密に ×0.8（弱マネージュ・ドレ 2000→1600、弱ランヴェルセ 1350→1080、OD ランヴェルセ 1500→1200）。
- SA最低保証（30/40/50%）はこの0.8倍が掛かった後でも保証として機能する＝クラシックの DR乗算補正と全く同じ位置・順序（④'）で効くと考えられる。
- **オーナー指示（2026-09-13）**: モダン計算では、簡易入力とコマンド入力の両方が使える技は**簡易入力を使った前提**で計算する（コマンド表示も簡易入力側を優先）。
- **判定方法**（`ruleset.ts` の `moveHasModernShortcutInput` / `isModernPenaltyEligibleCategory`）:
  - 対象カテゴリは `category:'special'` と `'super'` のみ（通常技・投げ・ドライブインパクトは対象外。マネージュ・ドレ等のコマンド投げは技辞典上 `category:'special'` なので対象になる）。
  - `Move.inputModern` が `Move.inputClassic` と**異なる文字列**を持つ技だけが対象（＝クラシックとは別の簡易入力手段が実在する技）。OD版の同時押し等、モダンでも入力方法自体がクラシックと変わらない技（例: `blanka-electric-od` は `inputModern` も `"214PP"` で `inputClassic` と同一）は対象外＝減衰しない。
  - `Move.inputModern` が未確認（`null`）の対象カテゴリの技は、減衰の有無を判断できないため `missing_modern_input` issue を出してそのヒットを結果から除外する（`status` は `'incomplete'` になる）。2026-09-13時点でマノン・ブランカの SA1〜3・CA は全て `inputModern` 未確認のため、SAで締めるコンボのモダン計算は軒並み incomplete になる。
- 使い方: `calculateComboDamage(combo, ruleset, 'modern')`。監査ツールは `npm run damage:audit -- --modern` または `/damage-audit/?modern=1`。

## 5. 既知の制限（未実装・意図的に対応していないもの）

いずれも「計算式のバグ」ではなく、**技辞典のスキーマ（1技=1つの `damage` 値）では表現しきれない技の仕様**。

- **強ロン・ポワン／弱ロン・ポワンの多段本質**：これらの技は本来2ヒットする技だが、技辞典の `damage`（例：強ロン・ポワン=800）は2ヒット分の合計値。浮いている相手に当てると1ヒットしか入らないため、実際のダメージは「段の残存率を掛けた値」のさらに約半分になる。`manon-jump-jhk-odfouette` / `manon-jump-jhk-hoseigiri` / `manon-punish-invincible-odfouette` の3例で、この「予測値のちょうど半分」というパターンが一貫して確認できている。技辞典が1技1 `damage` しか持てない現状のスキーマでは、ステップごとの「何ヒット目まで入ったか」を表現できないため未実装。
- **弱ロン・ポワン→SA3キャンセルの1段目のみヒット**：`manon-mid-5mp-lethal-sa3` で、キャンセル発生猶予の関係かごく早いタイミングでキャンセルされるため、上の「半分」よりさらに小さい値（実測21、技辞典基準の予測378との差357）になる。原因は上と同種（多段技の一部しか入らない）と考えられるが、「半分」という単純な比率では説明がつかない小ささで、技辞典の `damage(900)` 自体が正しいかも含めて要継続確認。
- ジャストパリィ後の反撃補正、ドライブインパクトのガード壁やられ補正（未確認・未実装）。
- モダン操作の簡易入力補正は実装済みだが（§4.9）、SA1〜3・CA を含め `Move.inputModern` が未確認の技が多く、対象コンボの多くが `incomplete` になる。実測値もまだ無く、クラシックほどの検証はできていない。

## 6. 検証方法

- CLI: `npm run damage:audit`（全件、クラシック）／ `npm run damage:audit -- <slugの一部> --hits`（該当コンボのみ、ヒット別内訳付き）／ `npm run damage:audit -- --modern`（モダン計算に切替。記録値はクラシック実測のままなので「差」は参考値）。
- ブラウザ: 開発サーバー起動中に `http://localhost:4321/damage-audit/`（本番ビルドでは404、`?modern=1` でモダン表示）。CLIと同じ内容を、ヒット内訳を展開できる表で確認できる。
- 実測値と食い違うコンボがあれば、対戦画面の各ヒットのダメージ・パーセンテージを確認し、上記のコマンドの出力（各ヒットの `stage` / `stagePercent` / 適用ルール）と突き合わせて原因を特定する、という運用で今回のロジックを確定した。
