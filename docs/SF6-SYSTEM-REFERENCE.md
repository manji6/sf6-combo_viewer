# SF6 のゲーム知識・情報源（AIエージェント向けリファレンス）

作成日：2026-09-22。このプロジェクトでコンテンツ登録・ダメージ計算等の作業をする際、Street Fighter 6 自体の仕組みについて何度も確認し直すことになった知識をまとめておく。**プロジェクト固有の実装**は他ドキュメント（`SPEC.md` / `CONTENT.md` / `DAMAGE-CALCULATION-MECHANISM.md`）を参照。ここは「SF6というゲームの仕組みそのもの」の話。

## 1. モダン操作の基礎知識

- **通常技にP/Kの区別が無い**。弱・中・強の各ボタンは、立ち／しゃがみ／ジャンプの状況ごとに**1つの技だけ**が固定で割り当てられる（例: ブランカの立ち強＝立ち強P。立ち強Kは直接ボタンでは出せない）。技辞典の `Move.inputModern` はこの「直接ボタンで固定の技」を表す。
- **アシストボタン（AUTO）は自動選択の連続技**。1つのボタンを連打すると、状況に応じて異なる技へ自動で連携する（例: ブランカのアシスト弱攻撃＝立ち弱K→しゃがみ弱P→エレクトリックサンダー）。この連携内容はキャラ固有で、技辞典の1フィールドでは表現しきれないため、実際にコンボへ落とし込む時はキャラ経験者への確認が必須（コミュニティのコンボ表は「アシスト◯攻撃」としか書いておらず中身が分からないことが多い）。
- **SPボタン＝必殺技/SA用の簡易入力**。方向＋SPで、コマンド入力の代わりに必殺技・SAを出せる。ただし**ダメージが80%（×0.8）に減衰する**。モダンでもコマンド入力（`inputModernPrecise`）で出せば減衰しない。詳細な計算順序は `DAMAGE-CALCULATION-MECHANISM.md` §4.9。
- **SA1〜3/CAの簡易入力は全キャラ共通コマンド**（2026-09-13 オーナー確認）:
  - SA1 = 前 or ニュートラル + 強攻撃 + SP
  - SA2 = 後ろ + 強攻撃 + SP
  - SA3 / CA = 下 + 強攻撃 + SP
- **OD必殺技の簡易入力は「AS（アシスト）+ SP」同時押し**が多い（表記は本プロジェクトでは `"6AS SP"` のように direction+AS+SP で統一）。

## 2. 主要システム用語（日本語表記 ↔ 意味）

| 用語 | 意味 |
|---|---|
| ドライブラッシュ（DR） | 生ラッシュ。前ダッシュ2回相当の入力でヒット・ガード後に接近しつつ攻撃を継続 |
| キャンセルドライブラッシュ（CDR / DRC） | 必殺技キャンセル可能な攻撃ヒット中に出すラッシュ。ダメージに乗算補正（0.85倍）が掛かる |
| ドライブパリィ | 中+強同時押しの先行入力ガード。パリィ成立中に前入れでパリィドライブラッシュ |
| ドライブインパクト（DI） | 強+強同時押しのアーマー付き突進技。パニッシュカウンター（PC）成立で追撃可能に |
| ドライブリバーサル | ガード中またはドライブパリィ成立中に出せる反撃技（本プロジェクトでは未実装・対象外） |
| パニッシュカウンター（PC） | 一部の技の硬直中にヒットさせた時の強化ヒット。基礎ダメージに×1.2、技によっては追加の性能変化（吹き飛び・膝崩れ等） |
| ジャストパリィ | パリィの中でも特定のタイミングで成立する上位版。相手を強制パニッシュカウンター状態にする |
| スーパーアーツ（SA） / クリティカルアーツ（CA） | SAゲージ消費の超必殺技。CAは体力25%以下でSA3が強化されたもの |
| メダル（マノン固有） | マネージュ・ドレ／ランヴェルセ／SA3・CAのヒットで蓄積し、ダメージが上昇するマノン専用ゲージ |
| ライトニングビースト（ブランカ固有） | SA2発動中の強化状態。必殺技の性質が変化し、ローリング系からローリングキャノンへ派生可能に |
| スタン（気絶） | ドライブゲージ・スタンゲージが尽きた相手が一定時間行動不能になる状態。技辞典の `opponentState` には専用の値が無いため `standing_hit` 等で代用している（要注意） |

## 3. ダメージ計算の仕組み

詳細・確定ロジックは **[DAMAGE-CALCULATION-MECHANISM.md](DAMAGE-CALCULATION-MECHANISM.md)** にまとめてある（段階補正・始動補正・コンボ補正・即時補正・DR乗算補正・SA最低保証・PC倍率・モダン簡易入力補正など）。ここでは要点だけ:

- 補正は「技」ではなく「ヒットの段（stage）」に紐づく残存率テーブルで決まる。技辞典の `comboScaling` は自由記述文字列で、正規表現でパースしている（`src/lib/damage/ruleset.ts`）。
- 一部の技（強/弱ロン・ポワン等）は「技辞典の1つの `damage` 値が実は2ヒット分の合計」という多段本質を持ち、状況によって片方のヒットしか入らないことがある。これは現行スキーマでは表現できない既知の制限（`DAMAGE-CALCULATION-MECHANISM.md` §5）。
- 実測値（オーナーが対戦画面で確認した値）による裏取りが最も信頼できる。community記事・Wiki等の値は候補・参考止まりで、そのまま採用しない。

## 4. 情報源の使い方

### 公式サイト（Capcom）

- フレームデータ: `https://www.streetfighter.com/6/ja-jp/character/<キャラID>/frame`
  （`/6/buckler/ja-jp/...` ではない。`buckler` 付きパスは404になることがある）
- コマンドリスト: `https://www.streetfighter.com/6/ja-jp/character/<キャラID>/movelist`
- **取得方法**: `get_page_text` でほぼ全部のフレームデータ（ダメージ・補正値・Dゲージ増減・SAゲージ増加・属性・備考）がテキストとして取れる。ただし**モダン操作のコマンド表記（SP/AUTO/AS等のボタンアイコンや方向矢印）は画像なのでテキスト抽出できない**。この場合は `computer` action `screenshot`/`zoom` で該当箇所を視覚的に読む必要がある（アイコンの色分け: 赤=強・黄緑=中・青=弱、が経験的にわかっている）。
- フレームデータのページは技によって「■クラシック操作」「■モダン操作時」でダメージが並記されていることがあり、比率を見るとモダンの減衰倍率（0.8倍）の裏付けになる。

### 二次情報源（コミュニティサイト・Wiki）

- 実際に使った例: `kamigame.jp`（コンボガイド等）。ここも**コマンド表記はアイコン画像**なので、`get_page_text` だけでは技名（「アシスト強攻撃」等）しか取れず、具体的な方向・ボタンは読めない。折りたたみ（アコーディオン）UIの場合、クリックして展開しないとDOMにテキストが出てこないこともある。
- 二次情報源の数値・レシピは「候補」として扱い、可能な限りオーナー（実際にプレイする人）の確認を挟んでから技辞典・コンボデータへ反映する。とくに「アシスト◯攻撃」のような自動連携の中身は、ガイド側の説明だけでは分からないことが多い。

## 5. データ登録で気をつけていること（このプロジェクトの一貫方針）

- 未確認の値は `null` のまま残し、"それらしい値" で埋めない（`docs/CONTENT.md` §7 と同じ方針）。
- 実測値（`damageConfidence: 'measured'`）と目安値（`'estimated'`、各技の基礎値合計など）を区別する。
- 技の「使用回」「ヒット数」といった概念は、技辞典のフィールド1つでは表現しきれないことがある（アシストチェーンの自動連携、強/弱ロン・ポワンの多段本質など）。無理にフィールドへ押し込めず、`notes` に制限事項を明記する。
