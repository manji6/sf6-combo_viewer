# SF6 ダメージ計算：追加ネット調査

調査日：2026-09-12。[設計資料](DAMAGE-CALCULATION-DESIGN.md)を補完する調査記録。計算器・ゲームデータは変更していない。

## 1. 結論

**ネット調査から計算モデルの候補はかなり具体化できる。特に、モダン補正の継承、SA の最低保証、補正率の丸めを設計へ追加すべき。** 一方、公式の対象版の本文と実ゲームの検証を完了していないため、以下を現行版の確定仕様とはしない。

- **資料で確認**：その著者が当該ルール・検証結果を記載していることを本文で確認した。
- **実装候補**：複数の資料や公開コードが支持するが、採用対象版の正解例との照合を残す。
- **未解決**：資料が古い、情報が衝突する、数値や適用順の検証が不足している。

検索結果の要約だけ、AI による攻略生成記事、別サイトによる転載は計算仕様の根拠に採用していない。主に検証者本人の記事と計算機作者のコードを読んだ。ページの更新日が新しくても、全項目がその日に再検証されたとは扱わない。

## 2. 基本ルールの実装候補

| 項目 | 資料から得られた候補 | 実装上の扱い |
|---|---|---|
| 通常の補正進行 | 特殊条件のない場合、100 → 100 → 80 → 70 → … → 10% | hit 数や moveKey の種類数へ直結させず、補正上の段の進行を定義する |
| コンボ中の DR | 0.85 の乗算、同一コンボで重ね掛けしない。コンボ前の生ラッシュ始動とは区別 | `DR使用回数` の累乗ではなく、適用状態と発生時点を持つ |
| DI ガード壁やられ | 0.8 の乗算。DI ヒットやスタンとは別条件 | `wall_splat` だけで一律決定せず、発生原因を開始条件に持つ |
| ジャストパリィ後の反撃 | 0.5 の乗算という説明 | 一般の始動補正と同じ減算欄へ流し込まない |
| SA 最低保証 | 一般則として SA1 30%、SA2 40%、SA3 / CA 50%。簡易入力でも保証を下回らない | 技別例外に対応できる保証ルール。保証処理の後からさらに一律 0.8 を掛けない |

この表の一般則は、検証・攻略メモを公開した[ハメコの記事（2023-07-01）](https://note.com/hameko/n/n933d2911d655)に記載されている。歴史的なルールの候補として採用し、個別技や現行版の例外をこの表だけで決めない。

追加・始動・即時の各補正については、値だけでなく適用イベントを分ける必要がある。[はるかの検証（2023-08-26）](https://note.com/libitina_dgh/n/n6dd052c3f434)は、追加分は後続、始動条件は最初に当てた場合、即時分は当該技から、という区別を説明している。また多段技の途中に別の攻撃が挟まる例を示している。これを踏まえ、**初回ヒット時の段数管理と、各着弾時の補正評価を別処理にする**のが設計上の結論。

単発に常に即時補正を掛ける、公式の「コンボ補正20%」を無条件で通常進行に20ポイント追加する、といった実装は避ける。基本分を含む値か、追加分かの正規化が必要である。

## 3. モダン補正：単一の inputMethod だけでは足りない

[豚平の独自検証](https://note.com/tonpeidon/n/nbc92c680a5cf)は 2024-04-21 公開、取得した本文の更新履歴は Act13（2026-08-10）まである。今回の対象に関係する報告は以下。

| 対象 | 著者の報告 |
|---|---|
| 通常の簡易必殺技・SA | 原則 0.8。アシストコンボ内の技と単独の SP 入力を区別 |
| マノンのグラン・フェッテ | 簡易入力したランヴェルセから派生すると、派生側のボタンによらず補正を継承 |
| 一部の攻撃型 SA | 簡易入力 SA のヒット後、後続技にも補正が残る |
| ブランカ SA1 | 爆弾が設置済みの場合など、後続へ補正が影響し得る |
| ブランカ SA2 | 簡易発動自体を理由に、後続のローリングキャノン等へ補正は付かない |

これらはゲーム内での挙動を調べた著者の報告であり、本調査者による実機再検証ではない。とくに後続補正と次の SP 入力を掛け合わせるかは、追加テストが必要。同記事の所感は二重に掛けない挙動を示唆するため、0.8 × 0.8 を既定にしない。

**設計への反映案（上の報告からの推論）：**

```text
inputMethod: 手動 / 簡易 / アシスト
inputOrigin: 当該操作 / 親の派生元
scalingScope: 当該技 / 派生系列 / 以降のコンボ
activation: 発動時 / 最初の命中時 / 個別条件
stackingGroup: 同じ補正を重複適用しないための識別子
```

名称は仮案。inputMethod から直ちに倍率を返さず、技プロファイルと親操作・状態から適用ルールを解決する。アシストボタンを押しただけの通常技と、アシストコンボ内で自動発動した必殺技を混同しない。SP / AS という表示文字列の有無を計算条件にしない。

## 4. 端数処理と最低保証：候補を比較できる形にする

### 4.1 確認できた説明と実装

[まゆげの解説・検証メモ（2024-04-04）](https://www.mayuge-purys.com/entry/2024/04/04/%E3%80%90%E3%82%B9%E3%83%886%E3%80%91%E3%83%90%E3%83%88%E3%83%AB%E3%82%B7%E3%82%B9%E3%83%86%E3%83%A0%E5%85%A8%E8%88%AC%E3%81%AE%E7%B4%B0%E3%81%8B%E3%81%84%E4%BB%95%E6%A7%98%E3%81%AB%E3%81%A4%E3%81%84)には、ラッシュの例で 59.5% を 59% に切り捨てる説明がある。ただし記事の一部に古い値や用語の混在があるため、記事全体を正解表にしない。

[nimparo の計算機の実装](https://github.com/nimparo/sf6.combocalc/blob/main/script.js)も、倍率を掛けた補正率を切り捨て、SA の最低保証で補い、最後に各入力行のダメージを切り捨てて合計する。作者は[計算機の説明](https://nimparo.github.io/sf6.combocalc/)で多段技の丸め誤差が残ると明記している。したがって比較対象には使えても、本アプリの正解値生成器にはできない。コードは閲覧のみで、転載・導入・実行していない。

### 4.2 候補となる処理の骨格

```text
1. 技の条件から基礎ダメージ・当該ヒットを解決する
2. 段の進行、開始条件、即時条件、現在有効な補正を評価する
3. 残存補正率へ該当する乗算を適用する
4. 補正率を所定の精度で丸める
5. 当該技・ヒットの最低保証を適用する
6. ヒットの基礎値へ適用し、ダメージの端数を処理する
7. 後続に影響する状態・予約された補正を更新する
```

資料を踏まえた骨格であり、全キャラ共通の確定アルゴリズムではない。CH / PC の増加分の適用順、多段 SA の保証対象、途中キャンセルや部分ヒット、状態依存ダメージでは個別ルールを必要とする。前後イベントの順序を記録して比較できるようにする。

### 4.3 丸め・順序の違いを検出する数値例

以下は **設計説明用に作成し、算術を確認した仮想例**。実在コンボの実測値ではない。実ゲームの正解 fixture に転用しない。

| 比較 | 方式 A | 方式 B | 判別できる違い |
|---|---|---|---|
| 基礎値 1,000、残存70%、DR係数0.85 | 率を59%にして **590** | 最後だけ切り捨て **595** | 率の丸めとダメージの丸め |
| 基礎値101の2ヒット、各59% | 各hitを切り捨て **118** | 基礎値202で一括計算 **119** | 多段技の合算タイミング |
| 基礎値4,000、残存50%、簡易0.8、保証50% | 簡易適用後に保証 **2,000** | 保証後に簡易適用 **1,600** | 最低保証の適用順 |
| 同条件で残存70% | 簡易適用後56%なので **2,240** | 常に保証値へ固定すると **2,000** | 保証は固定ダメージ化ではない |

実機ではこのように候補式の結果が分かれるコンボを選ぶ。端数の出ない例で一致しても、丸め方式の証拠にはならない。合計だけでなく最初に差が出るヒットと補正率を記録する。

## 5. マノン／ブランカへの具体的な影響

### マノン

現データの `manon-sa3.comboScaling` は、指定技からキャンセルした場合の即時15%のみ記載する。一方、上記[まゆげの資料](https://www.mayuge-purys.com/entry/2024/04/04/%E3%80%90%E3%82%B9%E3%83%886%E3%80%91%E3%83%90%E3%83%88%E3%83%AB%E3%82%B7%E3%82%B9%E3%83%86%E3%83%A0%E5%85%A8%E8%88%AC%E3%81%AE%E7%B4%B0%E3%81%8B%E3%81%84%E4%BB%95%E6%A7%98%E3%81%AB%E3%81%A4%E3%81%84)は通常の即時5%と、立強P・ロンポワンからキャンセルした場合の15%を区別する。

**データの欠落候補**として記録する。2024年の数値を直接書き足すのではなく、現在の対象版で「単発」「補正のあるコンボ途中」「指定キャンセル」の比較を行う。条件付き15%が通常5%への加算なのか置換なのかも仕様に明記する。重複して20%にしない。

メダル別の全ダメージ表と、各技でどの時点のメダルを参照するかは、今回の取得資料から確定できなかった。現データの「Lvで変動」という文章だけから SA3 等の数値表を生成しない。状態ごとの基礎値を埋める作業は DC-4 に残す。

### ブランカ

SA2 発動の damage が 0 であることと、その発動が補正に何もしないことは別問題。前節の「簡易入力による補正なし」は、即時補正など他種の補正もゼロという意味ではない。

[ﾁｰﾀﾗの SA2 研究（2023-11-18）](https://note.com/genexcheeetaran/n/n94ee2ac91640)には、強化中のローリングによる人形起動と、投げの後に人形が当たる連係の観察がある。ここからの設計上の結論は、設置・起動・着弾を分け、投げと爆弾をひとつの技合計へまとめないこと。記載された連係が現在も成立するという確認ではない。

SA2 中の各必殺技を全て一律1.1倍にする根拠や、人形の全ヒット配分・適用順を一次資料で確定できていない。`blanka-sa2.notes` の「ダメージが微増」を倍率へ変換しない。強化前後の技バリアント・補正プロファイルの差として調査する。

## 6. 食い違いと、混ぜてはいけない情報

| 論点 | 確認結果 | 対応 |
|---|---|---|
| 弱攻撃始動 | 2023年のハメコ記事は次段90%。2024年5月の実測比較記録は始動10→20%の変更を記載 | 古い例を現在のテスト期待値にしない |
| DR 係数 | はるか記事の本文は85%、末尾例には80%も登場。他の説明・公開計算機は85%を使用 | 85%を検証候補とする。内部の食い違いの理由を憶測で断定しない |
| 通常下限 | 一般説明の10%と、まゆげ記事の8%が一致しない | 乗算前の下限と乗算後の最終率を別フィールドにする。8%を共通下限として採用しない |
| モダンの後続影響 | 一般則「当該技のみ」に対し、独自検証は一部 SA・派生の例外を報告 | 基本則と技別例外を分け、継承・適用範囲を表現する |
| 公式の数値らしき転載 | 検索には転載・自動生成らしきページも出た | 公式本文で確認した値に昇格させない |

弱攻撃の更新については、[ゲームログブックの新旧比較（2024-05-22）](https://game-logbook.com/street-fighter6-202405assist/)を本文確認した。同じレシピでもダメージが変化した記録があり、計算ルールと技データを対象版ごとに固定する必要性を裏付ける。最新パッチへの適合は別途確認する。

公式サイトは `/6/buckler/.../character/.../frame` に加え、`/6/character/manon/frame`、`/6/character/blanka/frame`、変更履歴の個別パスも試した。取得エラー・403・Page cannot be found があり、公式本文の検証はできなかった。これはサイト全体が閲覧不能という断定ではない。SuperCombo Wiki も取得時に保護ページを返し、内容を根拠にしていない。

## 7. 開発へ渡す追加タスク

設計・スキーマ上は次を今回の調査で追加する。

1. **補正の範囲と起点**：当該技だけ、親の派生系列、コンボの残りを区別。適用開始と重複適用のルールを持つ。
2. **派生の由来**：表示上まとめられた command でも、計算上は親操作の入力方法を参照できるようにする。
3. **丸めの追跡**：倍率の生値、丸め後の補正率、最低保証適用後、ヒットダメージを別々に記録。
4. **条件付きルールの優先度**：通常値と条件別値を加算するか置換するかを明示。SA3 の例の二重加算を防ぐ。
5. **版と根拠**：source の公開日・更新日・実際の検証対象版を分ける。第三者検証、公式確認、オーナー実測を区別する。

次の少数比較で、残る不確定点を効率よく減らせる。

| ID | 比較する条件 | 確定する内容 |
|---|---|---|
| E01 | 現版で弱攻撃始動と通常始動 | 現行の基本進行・始動値 |
| E02 | 単発／コンボ途中／2回の DR | 適用開始と重複の扱い |
| E03 | 同じ後続を DI ヒット／ガード壁やられ／スタン後 | 開始条件と最初の段の数え方 |
| E04 | 端数が出るコンボ、同じ多段技の全段／部分ヒット | 率の丸めと各 hit の丸め |
| E05 | 保証付近の SA を手動／簡易で実行 | 最低保証とモダンの順序 |
| E06 | マノン SA3 の通常接続／指定技キャンセル | 基本即時補正と条件別補正 |
| E07 | マノンの親入力だけを変えたグラン・フェッテ | 派生への入力補正継承 |
| E08 | 簡易 SA 後の手動／簡易追撃、手動 SA との比較 | 後続補正と二重適用の有無 |
| E09 | ブランカ SA2 を手動／簡易発動し、同じ追撃 | 簡易補正と発動固有補正の分離 |
| E10 | メダル別単発と途中獲得、SA2前後、爆弾の着弾順 | キャラ状態と技バリアントのデータ |

各比較は、同じ対象版・同じ開始条件で行う。結果に合うように例外を後付けするだけでなく、想定したルールが別の例でも成立するか確認する。**ネットで分かった範囲はモデル候補へ反映済みで、残りは上の具体例に絞ってオーナー説明・実機確認を依頼できる状態。**
